The Strip Asks a Question, the Chart Answers It

The concept: a capped row of top-line numbers creates a question at a glance ("why does uptime look like that?"), and exactly one hero chart directly beneath it answers that question — never a second, unrelated chart competing for the same attention.

Fig. 1 — The hero chart's whole job is to explain the strip above it, not to introduce a new topic.

The tell that separates this from dashboard-with-rail: there is no persistent nav here at all. This is a single overview screen, not an app shell with sections to switch between — if the content genuinely needs section navigation, reach for dashboard-with-rail or holy-grail instead.
When Not to Use This Archetype

Content with no real top-line numbers

Manufacturing KPI tiles for a document that doesn't have any is worse than having none — see the Mostly Text variant for the honest alternative.

More than one hero-worthy chart

If two charts are both genuinely dominant, split the screen into two of these archetypes rather than fighting for one hero slot.

Content needing persistent navigation

A multi-section app belongs in dashboard-with-rail or holy-grail; this archetype is deliberately a single, rail-free screen.
